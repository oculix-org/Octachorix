1. POURQUOI OCTACHORIX EXISTE
-----------------------------------------------------------------------------

1.1  Le probleme mesure (Legerix issue #20, CI matrix run 32606359921)

     La memory map du hs_err complet montre DEUX libtesseract mappees
     simultanement sur Ubuntu + apt tesseract :
       - notre bundle  : ~/.cache/legerix/.../libtesseract.so.5      (5.5.0)
       - le systeme   : /usr/lib/x86_64-linux-gnu/libtesseract.so.5.0.3

     Le journal JVM enregistre juste avant le crash :
       UnsatisfiedLinkError: libtesseract.so: cannot open shared object
       UnsatisfiedLinkError: libleptonica.so: cannot open shared object

     C'est JNA qui cherche le nom exact non-versionne dans nos dirs, echoue
     (on ne ship que .so.5 et .so.6), puis bascule sur matchLibrary() qui
     scanne le pool fusionne (nos dirs + /usr/lib) et pick le max de version.
     "5.0.3" > "5" -> le systeme gagne.

     Le tesseract systeme est compile contre Leptonica 1.82.
     Notre Leptonica embarquee est 1.87.
     Struct Pix incompatible -> SIGSEGV pixDestroy des le premier cross.

1.2  Ce que tess4j fait et pourquoi ca ne suffit pas

     Verifie sur tess4j 5.18.0 et 5.20.0 (sources publiques GitHub) :

       - LIB_NAME_NON_WIN = "tesseract"  (constante hardcodee)
       - TessAPI.INSTANCE  (static final, init au classload)
       - getTessAPIInstance() fait Native.load(name, TessAPI.class)
         -> resolution short-name par JNA sur Linux/macOS
       - Aucun hook pour injecter un chemin absolu sur Unix
       - Sur Windows uniquement, tess4j extrait sa DLL et binde absolu

     Note importante : tess4j appelle dispose() dans les finally des
     operations publiques, et dispose() invoque bien TessBaseAPIDelete.
     Il n'y a PAS de fuite memoire chronique. Ce que tess4j n'expose
     pas, c'est un objet-session persistant dont le lifecycle est
     controle par le consommateur - il refait init/dispose autour de
     chaque doOCR/getWords.

     Aucune quantite de patchelf cote Legerix ne peut compenser le
     probleme de resolution short-name.

1.3  Ce qu'on gagne a ecrire notre propre couche

     - Chargement chemin absolu STRICT -> #20 meurt par construction
     - Un seul consumer moderne pour Legerix et OculiX -> plus de tess4j
     - Session persistante reutilisable avec lifecycle explicite
       (AutoCloseable) -> le consumer choisit quand init et delete
     - UNE SEULE PASSE DE RECONNAISSANCE pour texte + geometrie +
       confidences (au lieu de doOCR + getWords qui rerun recognition)
     - API typee : enums pour PageSegMode/OcrEngineMode/PageLevel,
       records pour les DTO, AutoCloseable pour la vie de la session
     - Multi-langue fluide via scribe.withLanguage("fra") -> nouveau
       Scribe partageant les natives, sans reconstruction complete
     - Licence GPLv3 -> protection contre absorption commerciale silencieuse
     - Nom, doctrine, structure sous notre controle direct

2. CONTRAINTES NON-NEGOCIABLES
-----------------------------------------------------------------------------

2.1  Licence GPL v3
     Modele iText/TigerVNC. Copyleft fort. Compatible dual-license
     commerciale future si un consommateur B2B demande une variante
     non-GPL. Ne PAS choisir Apache/MIT : la brique doit etre protegee.

     Consequence sur les contributions externes (Q8 tranchee) :
     Contributor Assignment Agreement (CAA) style FSF, pas simple CLA.
     Le contributeur assigne les droits patrimoniaux au projet, ce qui
     permet le relicensing commercial ulterieur sans avoir a re-solliciter
     chaque tiers. Fichier CONTRIBUTING.md a la racine du repo, avec
     texte du CAA a signer avant tout PR accepte.

2.2  Independent implementation

     "Independent implementation against the upstream Tesseract C API.
      No tess4j source code is copied or adapted."

     Concretement :
       - Les mappings JNA sont ecrits contre capi.h upstream Tesseract
         (docs C publiques -> signatures de fonctions = faits non
          protegeables par copyright)
       - La Javadoc PUBLIQUE de tess4j peut etre lue uniquement pour
         connaitre les NOMS de methodes que nos consumers attendent
         (setDatapath, doOCR, getWords) - le nom, jamais le corps
       - Le code source .java de tess4j n'est pas ouvert pendant
         l'ecriture d'Octachorix

     Note juridique : Apache-2.0 (tess4j) est compatible GPLv3 dans
     le sens Apache -> GPLv3, donc rien n'interdit legalement de
     reprendre du code tess4j sous GPLv3. Le choix "independent
     implementation" est un choix de propriete intellectuelle du
     projet, pas une contrainte de licence.

2.3  Chargement chemin absolu STRICT
     - NativeBond.bind(pathAbsolu, api, opts) uniquement
     - Sur Linux : RTLD_LAZY | RTLD_GLOBAL via JNA OPTION_OPEN_FLAGS
     - Sur macOS : NativeLibrary.getInstance(pathAbsolu, opts)
     - Sur Windows : NativeLibrary.getInstance(pathAbsolu, opts)
                     + SetDllDirectoryW pour les deps siblings (Windows only)
     - Fail loud si le fichier n'existe pas au chemin donne
     - JAMAIS de Native.load("tesseract") ni de short-name resolution
     - JAMAIS de fallback sur PATH / LD_LIBRARY_PATH / /usr/lib
     - Un seul mecanisme de chargement par OS
     - L'appelant fournit le chemin. Legerix le fournira. Point.

2.4  Zero dependance runtime a tess4j
     - Rien dans le pom.xml
     - Rien dans les imports
     - Meme les tests unitaires n'importent pas tess4j
     - Pas d'artefact Maven qui tire tess4j en transitif

4.2  NativeBond  (le loader - contrat generique)

     Role : charger UNE lib native par chemin absolu et retourner
            directement une interface JNA bindee. Un seul point qui
            maitrise chemin + flags.

     public final class NativeBond {
         private NativeBond() {}

         /**
          * Charge la bibliotheque au chemin absolu specifie et
          * retourne une instance de l'interface JNA passee en parametre.
          *
          * Un seul mecanisme de chargement par OS. Pas de fallback sur
          * short-name, PATH, LD_LIBRARY_PATH, /usr/lib.
          */
         public static <T extends Library> T bind(
             Path absolutePath,
             Class<T> apiClass,
             Map<String, ?> options
         );

         /** Surcharge sans options - defaults corrects par OS. */
         public static <T extends Library> T bind(
             Path absolutePath,
             Class<T> apiClass
         );
     }

     Contrat :
       - Path absolu obligatoire (assert isAbsolute, sinon OctachorixFault)
       - Fichier doit exister (Files.isRegularFile) - sinon OctachorixFault
       - Sur Linux : options par defaut = {OPEN_FLAGS: RTLD_LAZY|RTLD_GLOBAL}
       - Sur macOS/Windows : options par defaut = {}
       - Retourne l'interface JNA prete a l'emploi
       - Note : JNA cache NativeLibrary.getInstance() par path - deux
         appels avec le meme path retournent le meme handle sous-jacent,
         zero double load

     Usage :
       Hypercube api = NativeBond.bind(
           cacheDir.resolve("libtesseract.so.5"),
           Hypercube.class
       );

4.4  Scribe  (la facade - immuable + withLanguage pour multi-langue)

     Role : session Tesseract configuree, reutilisable pour N lectures,
            AutoCloseable pour liberer proprement le handle natif.
            Configuration figee au build ; changer de langue = nouveau
            Scribe partageant les natives (withLanguage).

     public final class Scribe implements AutoCloseable {

         // Construction uniquement par builder
         public static Builder builder();

         // API principale (peut etre appelee N fois sur la meme session)
         public Reading read(BufferedImage image);
         public Reading read(BufferedImage image, Rectangle roi);

         /**
          * Q3 - Multi-langue OculiX.
          * Retourne un NOUVEAU Scribe partageant les memes libs natives
          * (Hypercube instance, tesseract lib, leptonica lib) mais avec
          * son PROPRE handle TessBaseAPI* configure sur la langue passee.
          * Les autres options (datapath, PSM, OEM, variables) sont
          * heritees du Scribe courant.
          *
          * Chaque Scribe retourne par withLanguage() doit etre close()
          * independamment. Les libs natives restent chargees tant qu'au
          * moins un Scribe les utilise (cache JNA par path).
          */
         public Scribe withLanguage(String language);

         // Lifecycle
         @Override public void close();  // -> TessBaseAPIDelete, idempotent
         public boolean isClosed();

         // Meta
         public String tesseractVersion();
         public String language();

         // ---
         public static final class Builder {
             public Builder tesseractLibrary(Path absolutePath);   // requis
             public Builder leptonicaLibrary(Path absolutePath);   // requis
             public Builder datapath(Path tessdataDir);            // requis
             public Builder language(String lang);                 // requis
             public Builder pageSegMode(PageSegMode mode);         // optionnel
             public Builder ocrEngineMode(OcrEngineMode mode);     // optionnel
             public Builder variable(String key, String value);    // repetable
             public Scribe build();
         }
     }

     Contrat thread-safety :

       SCRIBE N'EST PAS THREAD-SAFE.

       Le handle TessBaseAPI* est un etat natif mutable. Sequence :
         SetImage(handle, imageA) ; Recognize(handle) ; GetUTF8Text(handle)

       Deux threads utilisant le meme Scribe se marchent dessus.
       Regle : un Scribe par thread concurrent. Pour un pool, allouer
       N Scribes. L'usage OculiX actuel (thread principal + sessions
       VNC per-thread) est deja compatible.

     Notes :
       - Le builder valide TOUT au moment de build() (fail-fast au boot)
       - close() est idempotent et libere le handle via TessBaseAPIDelete
       - withLanguage() cree un nouveau Scribe SANS toucher au courant :
         les deux vivent en parallele, chacun peut etre close() ou reutilise

4.5  Reading + TextElement  (les DTO - arbre plat)

     Reading = ce que retourne scribe.read().
     Une seule passe de RECONNAISSANCE (TessBaseAPIRecognize) produit
     l'ensemble ; les appels iterator/GetUTF8Text/Confidence/BoundingBox
     qui suivent parcourent le meme resultat sans re-reconnaissance.

     public record Reading(
         String text,
         List<TextElement> elements
     ) {
         /** Filtre l'arbre plat sur un niveau de segmentation. */
         public List<TextElement> elements(PageLevel level);
     }

     public record TextElement(
         String text,
         float confidence,       // 0.0 - 100.0
         Rectangle bbox,
         PageLevel level         // BLOCK, PARAGRAPH, TEXTLINE, WORD, SYMBOL
     ) {}

     public enum PageLevel {
         BLOCK,
         PARAGRAPH,
         TEXTLINE,
         WORD,
         SYMBOL;
         public int value();  // valeur C attendue par TessResultIterator
     }

     Notes :
       - Records Java (JDK 17+), immuables par nature
       - Reading.elements(PageLevel) filtre l'arbre plat deja calcule
         (plusieurs parcours d'iterator natif necessaires pour les 5
         niveaux, mais AUCUNE reconnaissance supplementaire)
       - TextElement contient DEJA son level -> le consumer sait ce qu'il tient
       - Rectangle = java.awt.Rectangle (deja utilise par TextRecognizer,
         zero conversion cote OculiX)

4.8  ImageBridge  (conversion BufferedImage -> PixelBuffer)

     Role : canonicaliser un java.awt.image.BufferedImage vers le format
            attendu par TessBaseAPISetImage(data, w, h, bpp, bpl).

     Pourquoi cette classe existe : un BufferedImage peut etre
     TYPE_INT_RGB, TYPE_INT_ARGB, TYPE_3BYTE_BGR, grayscale, indexed,
     custom raster. TessBaseAPISetImage attend un buffer coherent
     (bytes/pixel, bytes/ligne, ordre BGR ou RGB).

     tess4j delegue actuellement cette conversion a lept4j (via Pix).
     Octachorix vire lept4j cote Java -> il faut faire la conversion
     nous-memes.

     public final class ImageBridge {
         private ImageBridge() {}

         /**
          * Convertit un BufferedImage en buffer canonique
          * pret pour TessBaseAPISetImage.
          *
          * Supporte : TYPE_INT_RGB, TYPE_INT_ARGB, TYPE_3BYTE_BGR,
          *            TYPE_BYTE_GRAY, TYPE_USHORT_GRAY (converti en byte).
          * Les autres types sont convertis via getRGB() (plus lent).
          */
         public static PixelBuffer canonicalize(BufferedImage image);
     }

     public record PixelBuffer(
         byte[] data,
         int width,
         int height,
         int bytesPerPixel,     // 1 (grayscale) ou 3 (RGB) ou 4 (RGBA)
         int bytesPerLine       // = width * bytesPerPixel dans le cas simple
     ) {}
